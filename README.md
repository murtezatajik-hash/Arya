# آریا: دفتر حساب من

دفتر حساب شخصی برای ثبت درآمد و هزینه — بدون پرداخت. ساخته‌شده با Next.js (App Router)، TypeScript، Tailwind CSS، next-intl و Supabase Auth.

## اجرا

نیازمندی: Node.js 20.9 یا بالاتر.

1. نصب پکیج‌ها:

   ```bash
   npm install
   ```

2. ساخت فایل محیطی از روی نمونه:

   ```powershell
   Copy-Item .env.example .env.local
   ```

   ```bash
   # macOS / Linux
   cp .env.example .env.local
   ```

3. در Supabase وارد پروژه شوید و از مسیر **Project Settings → API** این دو مقدار را در `.env.local` بگذارید:

   ```env
   NEXT_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
   ```

4. در Supabase از مسیر **Authentication → URL Configuration** این مقادیر را تنظیم کنید:

   - Site URL: `http://localhost:3000`
   - Redirect URLs: `http://localhost:3000/**`

   برای محیط واقعی، دامنهٔ production را هم به همین بخش اضافه کنید.

5. مهاجرت‌های گاه‌شمار را روی پروژهٔ Supabase اجرا کنید. `supabase/migrations/20261109000000_calendar_hijri.sql` ستون‌های `calendar`/`hijri_offset`، سیاست INSERT برای ساخت پروفایل و مجوز لازم برای upsert را تنظیم می‌کند. `supabase/migrations/20261110000000_calendar_page.sql` ستون `holiday_sets` را اختیاری می‌کند (خالی یعنی «پیش‌فرض منطقه») و نوشتن روی جدول `holidays` را از نقش‌های `anon` و `authenticated` می‌گیرد. در **Supabase → SQL Editor** محتوای فایل‌ها را اجرا کنید یا با Supabase CLI:

   ```bash
   supabase db push
   ```

6. اجرای پروژه:

   ```bash
   npm run dev
   ```

   سپس [http://localhost:3000](http://localhost:3000) را باز کنید. به‌صورت پیش‌فرض به `/fa` هدایت می‌شوید.

   برای اجرای نسخهٔ production:

   ```bash
   npm run build
   npm start
   ```

   مقادیر `NEXT_PUBLIC_*` هنگام build در باندل کلاینت قرار می‌گیرند؛ بعد از تغییر `.env.local` دوباره build بگیرید.

> ورود و ثبت‌نام با ایمیل و رمز عبور از Supabase Auth استفاده می‌کند. برای تست محلی می‌توانید تأیید ایمیل (Confirm email) را در Supabase خاموش کنید یا اگر Supabase را به‌صورت محلی اجرا می‌کنید، ایمیل‌ها را از Inbucket ببینید.

## دستورها

| دستور | کار |
| --- | --- |
| `npm run dev` | اجرای محیط توسعه |
| `npm run build` | ساخت نسخهٔ production |
| `npm start` | اجرای نسخهٔ ساخته‌شده |
| `npm run lint` | بررسی ESLint |
| `npm test` | آزمون تبدیل تاریخ، شبکهٔ ماه، مناسبت‌ها، برج و ذخیرهٔ ترکیب‌های زبان/گاه‌شمار |

## ساختار

```text
messages/                 ترجمه‌های fa و en (تمام متن‌های رابط کاربری)
src/
  app/
    [locale]/             صفحه‌های چندزبانه
      (auth)/             ورود، ثبت‌نام، فراموشی رمز، تعیین رمز جدید
      ledgers/            فهرست دفترها، مدیریت دفتر، دفتر سه‌بخشی و صفحهٔ هر شخص
      calendar/           گاه‌شمار مستقل و تنظیمات تقویم، مناسبت و برج
      settings/           تنظیمات حساب و انتخاب گاه‌شمار
      dashboard/          هدایت سازگاری به /ledgers
    auth/callback/        تبادل کد ایمیل تأیید/بازیابی با نشست Supabase
  components/
    calendar/             شبکهٔ ماه، مناسبت‌های روز، برج و اتصال به دفتر
    ledgers/              فرم‌ها، ردیف‌ها و وضعیت دفتر
  i18n/                   تنظیمات next-intl و مسیرهای زبان
  lib/
    auth/                 نگاشت خطاهای Supabase به کلیدهای ترجمه
    calendar/             مناسبت‌ها، شبکهٔ ۴۲روزه و برج
    dates/                تبدیل، اعتبارسنجی و نمایش تاریخ میلادی/شمسی/قمری
    ledgers/              انواع، محاسبهٔ مانده و آخرین دفتر بازشده
    profile/              خواندن و ذخیرهٔ ترجیح‌های حساب مانند گاه‌شمار
    supabase/             کلاینت مرورگر، سرور و تازه‌سازی نشست
  proxy.ts                مسیریابی زبان + محافظت از مسیرهای خصوصی
supabase/
  migrations/             مهاجرت‌های SQL، از جمله ستون‌های گاه‌شمار و RLS پروفایل
```

## نکته‌ها

- زبان پیش‌فرض `fa` و جهت صفحه `rtl` است؛ زبان `en` با جهت `ltr` نمایش داده می‌شود.
- هیچ متن رابط کاربری داخل کد نیست؛ همه در `messages/fa.json` و `messages/en.json` قرار دارند.
- فونت فارسی Vazirmatn به‌صورت محلی از پکیج Fontsource بارگذاری می‌شود.
- مسیرهای `/ledgers`، `/ledgers/[id]` و `/calendar` بدون ورود قابل مشاهده نیستند؛ `src/proxy.ts` نشست Supabase را تازه می‌کند و دسترسی را کنترل می‌کند. مسیر `/dashboard` برای سازگاری به `/ledgers` هدایت می‌شود.
- «دفترها» و «گاه‌شمار» در ناوبری کنار هم قرار دارند؛ در موبایل نوار پایین و در دسکتاپ نوار کنار صفحه نمایش داده می‌شود و مسیر فعال با `aria-current` مشخص است.
- در Next.js 16 فایل `middleware` به `proxy` تغییر نام داده است؛ محافظت مسیرها در `src/proxy.ts` پیاده‌سازی شده است.
- مبلغ ثبت‌ها در دیتابیس همیشه عدد صحیح در کوچک‌ترین واحد ارز است (مثلاً ۱۲.۵۰ سامانی = ۱۲۵۰)؛ تبدیل و نمایش در `src/lib/money.ts` انجام می‌شود.
- تاریخ‌ها در دیتابیس همیشه میلادی و به شکل `YYYY-MM-DD` ذخیره می‌شوند؛ داده‌ها هرگز برای شمسی یا قمری تغییر نمی‌کنند. تبدیل شمسی با `jalaali-js` و تبدیل قمری با `Intl.DateTimeFormat` و تقویم `islamic-umalqura` در `src/lib/dates/calendar.ts` انجام می‌شود؛ نمایش در `src/lib/dates/display.ts` است.
- کاربر می‌تواند در `/settings` گاه‌شمار میلادی، شمسی یا قمری را انتخاب کند. انتخاب در `profiles.calendar` و اصلاح روز قمری در `profiles.hijri_offset` (از `-2` تا `+2`) ذخیره می‌شود. مقدار `NULL` یعنی کاربر هنوز انتخاب نکرده و زبان پیشنهادی تعیین می‌کند (`fa` → شمسی، `en` → میلادی).
- ذخیرهٔ تنظیمات با upsert انجام می‌شود تا اگر ردیف `profiles` وجود نداشت ساخته شود؛ این کار به زبان صفحه وابسته نیست.
- مرزهای ماه و سال در خلاصه با تقویم انتخاب‌شده، اصلاح روز قمری و منطقهٔ زمانی محلی کاربر محاسبه می‌شوند؛ فیلترها، نمایش ثبت‌ها، انتخاب تاریخ و صفحهٔ هر شخص هم از همین لایه استفاده می‌کنند.
- نام ماه‌های هر سه گاه‌شمار در `messages/fa.json` و `messages/en.json` قرار دارند و از زبان رابط کاربری پیروی می‌کنند، نه از نوع گاه‌شمار.
- آزمون‌های تبدیل تاریخ (میلادی، شمسی، قمری، اصلاح روز، مرز ماه/سال و رقم‌های فارسی)، شبکهٔ ۴۲روزه، مناسبت‌ها، برج و ذخیرهٔ شش ترکیب زبان/گاه‌شمار با `npm test` اجرا می‌شوند.
- صفحهٔ `/calendar` مناسبت‌ها را فقط از جدول `holidays` می‌خواند و هیچ نوشتنی روی آن انجام نمی‌دهد. هر ردیف با تقویم خودش (`jalali`، `gregorian` یا `hijri`) با روزها تطبیق داده می‌شود و فقط مجموعه‌های روشن `profiles.holiday_sets` نمایش داده می‌شوند. مقدار `NULL` یعنی پیش‌فرض منطقه: ایران شامل فرهنگ آریایی، ایران، اسلامی و شیعه؛ تاجیکستان شامل فرهنگ آریایی، تاجیکستان، اسلامی و اهل سنت؛ سایر مناطق شامل فرهنگ آریایی و اسلامی. آرایهٔ خالی یعنی کاربر همه را خاموش کرده است.
- مناسبت‌های قمری به رؤیت هلال وابسته‌اند و در جزئیات روز یادآوری و پیوند تنظیم `hijri_offset` نمایش داده می‌شود. منبع نامعتبر یا غیر `http/https` هرگز به پیوند تبدیل نمی‌شود و ردیف‌های تأییدنشده نشان «در حال تطبیق با منبع رسمی» می‌گیرند.
- برج امروز از تاریخ میلادی محاسبه می‌شود؛ تاریخ تولد اختیاری است و برج تولد را نشان می‌دهد. هر دو فقط جنبهٔ سرگرمی دارند و هیچ پیش‌بینی یا توصیه‌ای تولید نمی‌کنند.
- پیوند گاه‌شمار به دفتر، داده‌های مالی را جابه‌جا یا ادغام نمی‌کند. آخرین دفتر بازشده به‌صورت محلی به یاد می‌ماند، برای هر ماه فقط یک کوئری بازه‌ای روی `transactions.occurred_on` اجرا می‌شود، تعداد ثبت‌ها روی روزها نشان داده می‌شود و «ثبت تازه در این روز» همان فرم دفتر را با تاریخ همان روز باز می‌کند.
- ماندهٔ هر شخص فقط با ثبت‌های همان شخص و جدا برای هر ارز محاسبه می‌شود؛ ارزهای مختلف هرگز با هم جمع نمی‌شوند.
- PWA با manifest و service worker در `public/sw.js` پیکربندی شده است؛ فقط دارایی‌های ثابت و صفحهٔ آفلاین کش می‌شوند و صفحه‌های مالی و گاه‌شمار، پاسخ‌های Supabase، RSC و هر دادهٔ کاربر همیشه از شبکه خوانده می‌شوند.
